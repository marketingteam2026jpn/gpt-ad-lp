この記事の要点

  1. Pixelは、読み込まれるだけでは成果になりません。 データソース（Pixel ID）を作り、ページに設置し、購入や問い合わせが完了した場所でイベントを送り、そのイベントを成果イベントとして設定してキャンペーンに紐づけるまでが1セットです。公式のトラブル対応のヘルプも、Pixelが読み込まれていても、購入や問い合わせのイベントが送られていないことがあると書いています。
  2. Google タグマネージャー（GTM）での設置は公式に認められていますが、条件があります。 正しいページで読み込み、初期化とイベントの呼び出しを妨げたり順番を入れ替えたりしないことです。OpenAIのヘルプにGTMの設定手順はなく、タグマネージャーの「発火した」という表示だけでは送信の確認になりません。
  3. 動作確認は、実際の成果を1件起こし、「送られた→受け取られた→計上された」を順に確かめます。 debugモードのテストも集計から外れないため、テストの時刻・イベント名・イベントIDを記録します。広告に帰属した成果がレポートに載るまでは、24〜48時間ほど見込みます。

読んでほしい人：ChatGPT広告の成果の計測を準備する広告担当者と、Pixelを設置する開発者・タグの管理者。
この記事で扱わないこと：計測の全体像とUTMの設計は効果測定の記事、サーバーから成果を送る方法はConversions APIの記事、GA4との接続はGA4連携の記事、ビュー経由の成果の数え方はビュースルーの記事で扱います。

Pixelで成果が計上されるまでの4つの手順

GTMで設置するとき

ヘルプ（Measure Results）は、GTMで確実に読み込めない場合は直接設置かサーバー側の計測を使うよう案内しています。GTMのタグの種類やトリガーの設定手順は、確認した範囲のOpenAIのヘルプにも開発者向けドキュメントにも書かれていません。一方、2026年10月29日時点の計測パートナーのヘルプには、第三者のStapeがPixelとConversions APIのGTMテンプレートを提供していると載っています（10月7日時点のヘルプにはなかった記載です）。開発と保守は第三者が行い、手順はStapeのガイドを見るよう案内されています。

GTMで入れる場合に当社が確かめるのは、次の5点です。

  • 初期化（init）が、成果のイベントを送る呼び出しより先に動いている
  • 成果のイベントは、完了ページや送信完了のときにだけ動き、再読み込みで重ならない
  • 同意の管理ツールと連動させている場合、同意の前にPixelが送信しない
  • トリガーを、広告からの訪問（URLにopprefがあるとき）だけに絞っていない。2026年10月29日時点のヘルプは、opprefの付いた成果に限らず、送ってよい成果はすべて送るよう書いている
  • GTMのプレビューの「発火」だけで終わらせず、ブラウザのコンソールと通信まで確かめる（ヘルプも、タグマネージャーの「fired」の表示だけでは送信の確認にならないとしている）

画像タグ：JavaScriptを使わない送り方

画像タグは、Pixel ID・イベント名・データの種類をURLのパラメータに入れた非表示の画像で、ページの読み込み時に1つのイベントを送ります。同意が必要なサイトでは、同意を得てから画像を出します。opprefは自動で取らず、顧客情報も送れません。開発者向けドキュメントは、個人のデータ、セッションID、顧客ID、注文IDなどをどのパラメータにも入れないよう書いています。イベントIDもパラメータの1つなので、JavaScriptのPixelの例のように注文番号をそのままイベントIDにはしません（当社の読み）。

イベントの選び方と、金額の送り方

送るイベントは、標準イベントから選ぶのが基本です。開発者向けドキュメントは、標準イベントで表せない行動にだけカスタムイベントを使うよう書いています。標準イベントは12種類で、そのうちアプリのインストールと起動（app_installed・app_opened）はPixelでは送れず、Conversions APIだけで送ります。

イベント名と用途は開発者向けドキュメント（Supported Events）の記載で、事業の型への当てはめは当社の提案です。アプリの計測はアプリの記事で扱っています。

主な成果は標準イベントにしておくことを、当社は勧めます。理由は3つです。成果最適化（Conversion optimization）のキャンペーンで目標にできるのは標準イベント1つだけで（カスタムイベントは現在対象外）、作成後に変更できません。売上とROASの列（Order Created Sales・Order Created ROAS）は、order_created からだけ計算されます。イベント品質の評価には、閲覧・途中の行動・完了の各段階に標準イベントが届いているかを見る項目があり、この項目ではカスタムイベントは数えられません。ただしヘルプは、警告を消すために実際にない段階を作らないよう求めています。送るのは、実在する途中の行動だけです。

ページの読み込みには page_viewed を、特定の商品や記事の閲覧には contents_viewed を使います。contents_viewed は、ページの読み込みの後に起きた閲覧にも使えます。

カスタムイベントの名前は1〜64文字の英数字・アンダースコア・ハイフンで、英数字で始まって終わり、標準イベントと同じ名前は使えません（小文字が推奨）。Ads Managerの成果イベントの設定では種類を「Custom」にし、名前を送るイベントと完全に一致させます。表示名の一致では足りません。

金額は「通貨の最小単位の整数」で送る

金額（amount）は、ISO 4217にもとづく通貨の最小単位の整数で送り、金額を送るときは通貨（currency）も付けます。開発者向けドキュメントの例では、89.00米ドルは8900、8,900円も8900です。円はそのままの数になり、米ドルの例をまねて100倍にすると、売上が100倍で記録されます（当社の注意）。公式の購入の例は次のとおりです（Conversion Tracking。89.00米ドルの購入を、注文IDをイベントIDにして送る）。

oaiq(
  "measure",
  "order_created",
  {
    type: "contents",
    amount: 8900,
    currency: "USD",
  },
  { event_id: "order_12345" }
);

商品ごとの金額（contents の amount）は1単位の価格で、数量は quantity で別に送ります。イベントの amount は、イベント全体の金額です。1個3,000円の商品を2個だけ買い、値引きや送料などの調整がない注文なら、商品ごとの amount は3000、quantity は2、イベントの amount は6000です（当社の当てはめ）。2026年10月7日時点の説明は「商品ごとの金額（item-level monetary value）」で、10月29日時点で「1単位の価格。数量は別に送る」と明記され、計算例も加わりました（当社が保存した本文の比較）。単価×数量を入れていた実装は見直します（当社の見解）。

ヘルプは、売上を比べるときに税・送料・割引・手数料の扱いを確かめ、ブラウザとサーバーで同じ注文金額を送るよう書いています。どこまでを売上に含めるかは、先に社内で決めておきます（当社の提案）。

成果イベントの設定とキャンペーンへの紐づけ

成果イベントの設定（conversion event setting）は、どのデータソースのどのイベントを成果として数えるかを決めるもので、1つの設定で選べるデータソースは1つです。イベントが送られて受け付けられていても、キャンペーンに設定した成果イベントと一致しなければ、Ads Managerでは0と表示されます。正しい成果イベントは配信を始める前にキャンペーンへ紐づけ、設定を直しても過去のイベントは遡って計上されません（ヘルプ。効果測定の記事でも扱っています）。

開発者向けドキュメントは、クリックや表示（impressions）のキャンペーンでも、目的を変えずに成果イベントの設定を紐づけて計測できると書いています（APIの例。管理画面での紐づけ方はヘルプに見当たりません）。成果最適化のキャンペーンは作成時に標準イベントを1つ選び、後から変えられないため、目標にする行動はキャンペーンを作る前に決めます。

同意（Cookie）・CSP・顧客情報の扱い

同意が必要なサイトでは、初期化の前に止める

OpenAIのヘルプは、集めるデータを利用者に分かりやすく説明し、法令で必要な同意を得たうえで成果のデータを送るよう求めています。計測の数を増やすために同意の仕組みを外さないことも明記しています。Pixelには同意の機能があり、初期化の前に「同意なし」にして、同意を得てから「同意あり」に切り替えます。

oaiq("consent", false);
oaiq("init", {
  pixelId: "<YOUR-PIXEL-ID>",
});
// Call this after the user grants measurement consent.
oaiq("consent", true);

同意の状態は、false にしない限り、または保存された拒否がない限り、初期設定で true です。false の間はイベントを送らず、止めていた間のイベントは後から送り直されません。同意のバナーを出すサイトでは、同意しなかった人や同意の前の成果は計測されない前提で数字を読みます（当社の見解）。国内の法令（個人情報や外部への送信の扱い）への対応は、OpenAIの説明とは別に、自社のプライバシーポリシーと合わせて確かめます。

なお、イベントの opt_out は将来の利用者ごとのパーソナライズから外す項目で、計測は止めません（OpenAIは現在、Pixelのデータをこの用途に使っていないとしています）。

PixelのCookieとCSP

同意がある場合、Pixelはサイトのファーストパーティ Cookie を2つ使います。参照値（oppref）を入れる __oppref は30日で、URLのopprefを受け取るたびに30日に戻ります。ランダムに作るブラウザの参照値を入れる __obref は作成から365日です。consent を false にすると両方が削除されます。この保存期間は、成果の帰属期間やデータの保管期間とは別です。

CSP（コンテンツセキュリティポリシー）を設定しているサイトでは、次の送信先を既存のポリシーに足します。Pixelのためだけに 'unsafe-inline' を足さず、nonceかハッシュで許可するよう書かれています。

顧客情報：自動詳細マッチングと手動の送信

自動詳細マッチング（automatic advanced matching）は、広告のクリックの識別子が得られないときに、成果を広告に結びつけるための仕組みです。サイトのフォームなどから対応する顧客情報をPixelが見つけ、ブラウザの中で正規化してSHA-256でハッシュ化し、成果のイベントに添えます。元の顧客情報はこの仕組みでは送られず、実装の変更も不要です。成果最適化のヘルプは有効にするよう勧め、開発者向けドキュメントはAPIで作ったWebのPixelは自動で使うとしていますが、管理画面での設定の場所はヘルプに見当たりません。

顧客情報を自分で送る場合は、初期化（init）に user の項目を付けます。メールアドレス・電話番号・氏名・自社の顧客IDは正規化してからハッシュ化し、国・都道府県・市区町村・郵便番号はハッシュ化せずに送ります。正規化とハッシュ化の規則はConversions APIと同じで、Conversions APIの記事で扱っています。どちらの方法も、プライバシーポリシーと同意の設計に照らして使うかを決めます（当社の見解）。

動作確認の手順

計測のトラブル対応のヘルプは、完了した購入や問い合わせを1件起こし、何がいつ起きたかを記録してから確かめるよう勧めています。当社は次の順番で確かめます。

  1. 記録を作る。 テストする行動、時刻（タイムゾーンも）、イベント名、イベントIDを記録し、テストであることを社内の記録に残す
  2. 送信を確かめる。 テスト中は init に debug: true を加え、ブラウザのコンソールでPixelの動きを、通信（ネットワーク）でイベントのリクエストが出ているかを見る
  3. 受信を確かめる。 開発者は、利用できる場合、Advertiser APIで直近のイベント（recent events）を取り、イベントの種類・データソース・経路（ブラウザからは pixel_sdk）を確かめる。直近およそ15分の見本で、履歴や帰属の結果ではない
  4. 計上を確かめる。 24〜48時間ほど後に、Ads Managerの「Edit columns」で成果イベントの列を足し、広告のクリック（または対象の表示）の後に起きた成果が載るかを見る。広告を経ていないテストの成果は、届いていても計上されない
  5. イベント品質を見る。 データソースのイベント品質の警告を確かめる。直近の7日分（暦日）をもとに毎日更新され、設定を直した後の改善はゆっくり表れる。スコアが低い・出ないだけでは、計測が壊れているとは言えない

ヘルプは、Pixelのdebugモードは動きを記録するだけで、テストのイベントを集計から外さないと書いています。架空の購入を作ったり、時刻を変えて結果を合わせたりしないことも求めています。実装のテストが成功しても、広告に計上されるとは限りません。計上されるのは、キャンペーンの成果イベントと一致し、帰属期間の中で、対象となる広告のクリック（ビュー経由では表示）と結びつけられたときです。

この記事で分からないこと

  • 管理画面でPixel IDと成果イベントを作る具体的な操作。 ヘルプには「成果（Conversions）の画面」「Data Sources」までしか書かれていません
  • クリック・表示のキャンペーンに、管理画面で成果イベントを紐づける場所。 開発者向けドキュメントにAPIでの方法があるだけです
  • 自動詳細マッチングを管理画面でオン・オフする場所と、管理画面で作ったPixelの初期の状態。
  • Pixelを初期化しただけで、ページの閲覧（page_viewed）が自動で送られるか。 記載がないため、必要なら measure で送る前提で設計します
  • OpenAIが用意したGTMのテンプレートや設定手順。 確認した範囲にはなく、第三者のStapeのテンプレートが紹介されています
  • 日本のShopifyストアで、公式アプリのPixelが使えるか。 2026年10月29日時点のヘルプは、米国の全Shopify事業者に提供中で、ChatGPT広告の提供地域でもまもなく使えるようになると書いており、時期は書かれていません
  • 成果の合計にビュー経由を含めるか。 ヘルプと開発者向けのPixelのページで記述が分かれています（よくある質問を参照）

実装担当に渡すチェックリスト

  • [ ] 成果の地点（URLまたは操作）と送る標準イベントを決めた。カスタムイベントは標準イベントで表せない場合だけにした
  • [ ] 同じサイトで使うデータソース（Pixel ID）を1つにした
  • [ ] 成果を測るすべてのページ（決済・予約・ログイン後・転送先を含む）の<head>の上部にPixelを置いた
  • [ ] GTMで入れる場合、初期化がイベントより先に動き、成果のイベントが完了のときだけ動くことを確かめた
  • [ ] 同意が必要なサイトでは、初期化の前に consent を false にし、同意を得てから true にしている
  • [ ] CSPを使うサイトでは、必要な送信先をポリシーに足した
  • [ ] 転送やLP内の移動で、URLのopprefを落としていない
  • [ ] 金額は円の整数（8,900円なら8900）で送り、税・送料・割引を含めるかを決めた
  • [ ] 同じ行動には同じイベントIDを、別の行動には別のイベントIDを使う
  • [ ] 成果イベントを設定し、配信を始める前にキャンペーンへ紐づけた
  • [ ] テストの時刻・イベント名・イベントIDを記録し、送信・受信・計上を順に確かめた

よくある質問

Q. Pixelを入れると、何が自動で行われますか。 開発者向けドキュメントによると、LPのURLから参照値（oppref）を取ってCookieに保存すること、イベントに送信元のページのオリジンと時刻を付けること、近い時間のイベントをまとめて送ることです。自動詳細マッチングが有効なら、フォームなどの顧客情報のハッシュ化も自動で行われます。購入や問い合わせのイベントは自動では送られないため、完了したときに measure で送ります。

Q. 1つのサイトで、複数の広告主やブランドの成果を測れますか。 測れます。開発者向けドキュメントによると、SDKを1回だけ読み込み、Pixel IDごとに初期化します。measure は初期化済みのすべてのPixel IDに送られ、measureSingle を使うと1つのPixel IDだけに送れます。後から初期化したPixel IDは、それより前のイベントを受け取りません。

Q. 問い合わせフォームが外部のサービスで、完了ページにタグを置けません。 ヘルプは、予約サイトや埋め込みのフォームでは、LPのPixelが動いていても計測できているとは限らないと書いています。まず、そのサービスが計測タグの設置に対応しているかを確かめます。対応していなければ、受け付けたデータをサーバーや顧客管理の仕組みから、Conversions APIや計測パートナーで送る方法を検討します。その場合、広告のクリックの参照値（oppref）をどう受け渡すかを設計に含めます（当社の提案）。

Q. テストの購入は、本番の数字に入りますか。 入る可能性があります。ヘルプは、Pixelのdebugモードはテストのイベントを集計から外さないと書いています。テストの時刻・イベント名・イベントIDを記録しておきます。画像タグの開発者向けドキュメントは、テストの送信にはできればテスト用のPixel IDを使うよう書いています。サーバーから送る場合は、保存せずに検証だけを行う validate_only が使えます（Conversions APIの記事）。

Q. ビュー経由の成果を測るために、Pixelを変える必要はありますか。 必要ありません。同じイベントがクリック経由とビュー経由の両方に使われます。ただし、成果の合計（Conversions）にビュー経由を含めるかは、2026年10月29日時点でも記述が分かれています。ヘルプ（Measure Results、計測のトラブル対応）は「ビューの帰属期間が1日なら含める」、開発者向けのMeasurement Pixelのページは「キャンペーン単位の別の指標で、合計には含めない」です。自社のAds Managerで帰属期間の設定と内訳を確かめてください（ビュースルーの記事）。

まとめ

  • Pixelは、Pixel IDの作成、ページへの設置と初期化、成果の地点でのイベント送信、成果イベントの設定と紐づけ、の4つがそろって成果が計上される
  • GTMでの設置は公式に可。初期化とイベントの呼び出しを妨げず、順番を変えないこと。確かめるのはブラウザの通信
  • 主な成果は標準イベントにする。成果最適化の目標・売上の列・イベント品質の評価が標準イベントを前提にしている
  • 金額は通貨の最小単位の整数。8,900円なら8900。商品ごとの amount は1単位の価格
  • 同意が必要なサイトは初期化の前に止め、同意の後に再開する。止めていた間のイベントは送り直されない
  • テストは実際の成果1件で、送信・受信・計上を順に確かめる。debugモードのテストも集計から外れない

Pixelの設置箇所とイベントの設計を一緒に確かめたい場合は、成果の地点のURL、現在のタグの設置状況（GTMの利用の有無など）、同意バナーの仕様をお手元に用意のうえ20分の無料相談をご利用ください。
