ChatGPT広告の商品フィードの作り方｜必須項目・アップロード・フィード広告の作成手順

企画・編集：GPT広告専門店（株式会社Ikigai）公開：2026年10月29日／情報確認：2026年10月29日

ChatGPT広告の商品フィード広告（ベータ）は、商品ファイルを取り込んでから、キャンペーン・広告グループ・テンプレートを作ります。

本記事は、OpenAIの公式ヘルプと開発者向けドキュメント（Product Feeds、商品ファイルの仕様、Delta Feeds API ほか。いずれも2026年10月29日に取得）に基づいています。当社は日本のアカウントで商品フィードを作成・配信して確かめてはいません。手順の整理と提案は、株式会社Ikigaiの見解です。

この記事の要点

  1. 商品フィードは「ファイルを作る→取り込む→件数を確かめる→広告グループで商品を絞る→テンプレートを作る」の順で作ります。 商品ファイルは1行に1つの商品（色・サイズ違いは別の行）で、必須は9項目です。取り込んだ商品は2週間で失効するため、公式はホストURLかSFTPでの自動更新を勧めています。
  2. 取り込みの成功と、広告に出せることは別です。 2026年10月29日時点のヘルプは、フィードの4つの件数は商品ではなくオファーの記録の数で、差し引いても足りない商品の数にはならないと書いています。Productsタブは配信の実績がある商品だけを表示します。
  3. 価格と在庫は、変わったときに送り直します。 セール期間の日付を入れても価格は自動で切り替わらず、行を消した商品も最大14日残り得ます。販売を止める商品は在庫切れ（out_of_stock）と明示します。日本のアカウント・日本円のカタログで使えるかは、原典に明記がありません。

読んでほしい人：商品点数の多いEC・小売で、ChatGPT広告の商品フィード広告を試したい広告担当者と、フィードを作る技術担当者。
この記事で扱わないこと：公開事例の施策の読み方はEC事例の記事、Shopifyの公式アプリはShopifyの記事、年末の販促の準備は年末商戦の記事で扱います。

商品フィード広告とは：提供の段階と、日本で確かめること

商品フィード広告は、小売の広告主が商品カタログ（フィード）をAds Managerに取り込み、その商品情報から広告を作る仕組みです。ヘルプは、商品が多い、または頻繁に変わる小売の広告主向けと説明しています。

ベータ。フィードの商品はベータ期間中、広告にだけ使われ、ChatGPTの通常の会話には出ない

広告の作り方

広告グループで商品を絞り、テンプレート1つから広告を作る

商品ごとに広告を作らなくてよい

日本で使えるかは、原典に明記がありません。手がかりは次の3つです。

  • 商品ファイルの仕様。 ChatGPTの商品検索と広告で共有する文書は「標準の形式のアップロードは現在米国向け」と書き、行ごとの国の列や通貨を書いてもこの既定は変わらず、他の市場はOpenAIが連携と使える国・通貨を確認してから使うとしています。一方、広告向けの開発者ドキュメントは、例を米国のカタログと米ドルとしたうえで「カタログと広告アカウントに合う国・商品情報・通貨を使う」と書いています。
  • 他の国の例。 OpenAIの公式事例（2026年10月26日掲載）では、耳栓ブランドAVが市場ごとに言語・通貨・価格を合わせたフィードを用意し、EUで商品フィードのキャンペーンを運用しています。日本の例ではありません。
  • Shopifyアプリ。 2026年10月29日時点のヘルプでは、使えるのは米国のShopify事業者です（「よくある質問」）。

当社は、Ads Managerの「Tools」タブに「Feeds」があるか、作成の案内で日本を選べるかを、最初に画面で確かめることを勧めます。

始める前に決める4つのこと（当社の提案）

1. 広告に出す商品

全商品を一度に入れる必要はありません。ファイルの共通の手引きは、最初に100件ほどの少ない見本で検証し、最初の全件の取り込みを点検してから自動化するよう勧めています。

広告ポリシーで出せない商品は、最初から対象外にします。例えば酒類（アルコール0.5%超）とたばこは現在不可で、サプリメントは国別の表で「米国以外は不可」です。対象外の商品は、広告用の項目 is_ads_eligible を false にします（審査は審査の記事）。

2. 市場と通貨

フィードは、対応する国と通貨を決めて作ります（APIでは作成時に国を指定します）。複数の国へ出すなら、国ごとに言語・通貨・価格を合わせたフィードを用意する前提で設計します（耳栓ブランドAVの事例と同じ考え方）。

3. 更新の方式と担当

商品は2週間で失効するため、手作業のアップロードだけでは、更新を忘れた商品から広告に使えなくなります。誰が、何時に、どの方式で送り直すかを決めます。

4. 商品ページと画像を外部から開けるか

商品ページと画像は、公開されたHTTPSのURLである必要があります。商品フィードでは、OAI-AdsBotに加えてOAI-SearchBotが商品画像のURLを読めるようにし、画像のホストが403を返すとフィードの処理が止まることがあると書かれています（リンク先のクローラー許可の記事）。

商品ファイルの作り方：必須の9項目と、広告用の項目

商品ファイルは、UTF-8の文字コードで、1行に1つの商品（購入できる単位）を書きます。色やサイズの違いは別の行にします。必須の項目は次の9つです。

項目名

内容

注意

item_id

商品（バリエーション）ごとの固定のID

別の商品に使い回さない。先頭の0を残すため文字列で扱う

title

商品名。バリエーションがあれば色・サイズも含める

150文字以内が目安

description

商品の事実の説明

プレーンテキストで5,000文字以内が目安

url

商品の詳細ページ

できればバリエーションを選んだ状態のURL

brand

商品ページに書かれたブランド名

仮の値を入れない

seller_name

販売者の名前

仮の値を入れない

image_url

そのバリエーションの主な画像

JPEG・PNGなど画像そのもののURL

availability

在庫の状態

in_stock・out_of_stock・pre_order・backorder・unknown のどれか。空や不明な値は行ごと取り込まれない

price

通常の価格

金額・半角スペース・通貨コード。例：79.99 USD

価格は「金額＋半角スペース＋3文字の通貨コード」で、桁区切りのカンマを入れず、通貨が持つ桁より細かい小数を書きません。日本円なら「2980 JPY」の形になります（当社の当てはめ）。ただし仕様は、通貨や商品URLを書いても配信先の市場は決まらないとしています。日本円のフィードを使えるかは前の節のとおり未確認です。

任意の項目のうち、商品広告の見え方や運用に関わるものは次のとおりです。

  • sale_price：セール価格。通常の価格より低く、同じ通貨であること。条件に合わない値は使われません
  • group_id・listing_has_variations・variant_dict：バリエーションをまとめる項目。同じ商品の色・サイズ違いに同じ group_id を付けます
  • gtin・mpn：GTIN（8・12・13・14桁の商品コード）と型番。割り当てがなければ空にし、値を作りません
  • review_count・star_rating：商品の口コミの件数と平均（0〜5）。ストアの評価と混ぜません。広告の「星」にどの項目が使われるかは書かれていません

広告に使うための項目は2つです。

項目名

内容

is_ads_eligible

true で広告の処理の対象、false で対象外。Ads Managerで作ったフィードは、false と明示した商品を除いて既定で対象になる（ヘルプ）

ads_metadata

広告グループで商品を絞るための独自の値。例：{"custom_label_0":"summer"}。CSVのセルにはJSONの形で入れる

不明な任意の項目は空にし、「null」「n/a」のような仮の文字を入れません（在庫の unknown は例外）。カンマや引用符を含むセルは二重引用符で囲み、中の引用符は2つ重ねます。当社は、既定に頼らず is_ads_eligible を全行に明示することを勧めます。出している商品をファイルで確かめられるからです。

取り込みの方法と、2週間の失効

フィードは、Ads Managerの「Tools」タブ→「Feeds」→「Create Feed」から作ります。取り込みはフィードの行の「…」（三点）メニューから選びます。

方法

ヘルプが挙げる向いている場面

運用の注意（当社の見解）

CSV・TXTのアップロード

始めるとき、たまに手で更新するとき

2週間で失効するため、検証用と考える

ホストURL

商品カタログが固定のHTTPSのURLで公開されているとき

URLを変えない。認証やボット対策で止めない

SFTP

技術チームがサーバー間の送信を自動化するとき

接続の情報（パスワードか鍵）を社内で管理する

ヘルプは、商品が2週間で失効するため、ホストURLか自動のSFTPを勧めています。処理には、フィードの大きさにより数分から数時間かかり、結果は「Upload History」で確かめます。

SFTPで送る場合、開発者向けドキュメントには次の決まりがあります。

  • ファイルはSFTPの最上位のフォルダに直接置き、フォルダを入れ子にしない
  • 複数のファイルに分けるときは、全体で1つのカタログになるようにし、同じ商品を2回入れない
  • 既存のファイルを置き換え、古いファイルは消す（同じファイル名を使い回すと管理しやすい）
  • 送るたびに、在庫切れにする商品も含めた全件を送る

ファイルの共通の手引きは、全件の送り直しを少なくとも1日1回と勧めています。全件のファイルから消えた商品も、最後に処理した記録が最大14日残るため、販売を止めた商品は行を消さず在庫切れ（out_of_stock）として送ります。

APIには、10月7日時点の文書になかった「全件の送信でカタログを置き換える」設定が、10月29日時点で載っています。有効にすると、以後の全件のファイルに無い商品は1日以内に削除され、設定を戻しても削除済みの商品は戻りません。毎回全件を送れる仕組みが先に要ります。

取り込みの確認：件数の読み方と、よくある不備

取り込みのエラーが出たら、ヘルプは個々の行の値を仕様と照らすよう書いています。見るのは、必須の項目の抜け、仕様と違う項目名、形式の違う値の3つです。エラーの文言がホストURLに触れていても、CSVの中身を確かめます。

2026年10月29日時点のヘルプには、件数の読み方が加わりました（10月7日時点にはなし）。「Items in Feed Connection」の横の情報のツールチップで、4つの件数を見られます。

件数

読むときの注意（ヘルプの記載）

Ingested・Processed・Not approved・Ready

商品ではなくオファーの記録の数。件数ごとに対象の範囲が違うため、差し引いても足りない商品の数にはならない

Not approved

合計の数だけ。対象の商品の一覧や、商品ごとの理由は出ない

審査・Productsタブとの関係

ポリシーで承認されても配信の準備ができたとは限らない。Productsタブ（配信の実績がある商品）とは別に読む

APIでは、処理の状態と診断のコードが返ります。処理が終わっても、すべての商品を配信できるとは限りません。開発者向けドキュメントにある主な診断と対処は次のとおりです。

症状

確かめること

必須の列が無い（missing_required_column）

列の名前を仕様と照らし、足りない必須の列を足す

値が不正（invalid_value）

指摘された項目の形式。例：価格の金額と通貨コード

フォルダの構成の誤り（invalid_sftp_directory_layout）

ファイルを最上位に置き、入れ子のフォルダを消す

広告グループの商品数が0

絞り込みを外して数を見る。外しても0なら取り込みの履歴を見る

Productsタブは、配信前なら空や少なくても想定どおりのことがあり、配信が始まってから最初の行が出るまで最大7時間かかります。商品が全部あるかの確認には使えないため、配信前は広告グループを作る画面の商品数で確かめます。配信後も商品が出ないままなら、ヘルプは広告アカウントID、フィードID、キャンペーンと広告グループの名前、期間とタイムゾーン、商品IDの例、Productsタブの画面を添えてサポートへ連絡するよう書いています。

キャンペーン・広告グループ・テンプレートの作り方

ヘルプの手順を、決めることごとに分けると次のとおりです。

  1. キャンペーン：「Campaigns」タブで新しいキャンペーンを作り、キャンペーンの種類で「Product feed」を選ぶ。ほかの設定は通常のキャンペーンの作成のヘルプに従う。地域は国単位だけ
  2. 広告グループ：使うフィードを選び、商品の絞り込み（フィルター）をかけ、画面の商品数で対象の数を確かめる。入札の方法は、対象の新しい広告グループでは「Maximize results」（成果を最大化）が既定
  3. テンプレート：広告グループに1つ作る。現在テンプレートで選べるのは画像の項目だけ。見本の商品のプレビューで、タイトルと説明の見え方を確かめる
  4. 公開前の確認：フィード、商品数、商品の表示とリンク先、プレビュー、予算・入札・地域を見てから審査に出す

絞り込みと独自のラベル

絞り込みには、ブランド・カテゴリ・価格・商品IDなどを使えます。開発者向けの説明では、複数の条件はすべてを満たす商品だけが選ばれます。条件に合っても表示が保証されるわけではありません。

足りなければ、商品ファイルの ads_metadata に独自の値を入れて絞ります。ヘルプは bidding_tier（入札の段階）や product_line（商品の系統）のような値の例を挙げています。開発者向けの仕様は「連携で設定されたキーを使い、ターゲティング用のキーを作り出さない」としているため、使えるキーは設定の時点で確かめます。

ラベルで配信地域は絞れません。 ヘルプの例では、custom_label_0 に「WA」（ワシントン州）と入れても、その商品が選ばれるだけで、ワシントン州の人に配信が限られるわけではありません。

入札と目的

開発者向けドキュメントでは、商品フィードのキャンペーンも表示・クリック・成果（コンバージョン）の目的を使えます。成果の目的はクリック課金で、作成時に標準の成果イベントを1つだけ付けます。キャンペーンの種類・目的・つないだフィードは作成後に変えられません（APIの記載。管理画面で同じかはヘルプに記載なし）。購入の計測はPixelの記事を参照してください。

商品URLのトラッキング：旧方式は2026年11月5日までに移行

商品フィードの広告では、個々の商品に設定できる広告がなく、広告に設定したトラッキングのパラメータが各商品のURLに付きます。開発者向けドキュメントによると、新しい方式では、アカウント・キャンペーン・広告グループ・広告で設定した値が、商品URLにある同じキーを上書きします。商品URLの値が優先される旧方式（Legacy）のアカウントは2026年11月5日までに移る必要があります。切り替えは、アカウントの管理者がAds Managerの「Feed tracking is changing」の案内で「Switch now」を選びます（管理者以外は選べません）。切り替えの影響はEC事例の記事で扱っています。

既にある商品フィードから、ChatGPTやCodexのプラグインでキャンペーンを作ることもできます（Ads Managerプラグインの記事）。

価格・在庫の変更とセール

商品ファイルの仕様は、セールの期間や在庫の予定日を入れても、価格や在庫は自動で切り替わらないと明記しています。セールの開始と終了のときに、その時点の価格を送り直します。

変えたいこと

方法（原典の記載）

セール価格を始める・終える

sale_price を入れる・外して送り直す

売り切れ・再入荷

availability を out_of_stock・in_stock にする。在庫切れの商品は、変更が反映されると配信の対象から外れる

新しい商品を足す・画像や説明を変える

全件のファイルを送り直す

既存の商品の題名・価格・在庫だけを変える

APIのDelta Feeds APIも使える（広告アカウントごとに有効化が必要）

Delta Feeds APIは、変わった項目だけを送る仕組みです。応答の accepted: true は受け付けたという意味で、配信の対象まで更新されたことは示しません。価格は通貨の最小単位の整数で送ります（日本円は 7999 が7,999円という記載。日本円のフィードを使えるかは未確認）。送った変更は元のカタログにも反映し、次の全件の送信に意図した値が入るようにします。

フィードの価格と商品ページの価格は、同じ時点でそろえます（当社の提案）。広告ポリシーは、価格についての根拠のない主張を含む誤解を招く広告を禁じ、リンク先が広告の商品を正確に表すことを求めています。2026年10月30日から新規・既存のキャンペーンで自動的に有効になるクリエイティブ強化について、ヘルプは広告とLPの価格・販促・在庫を最新に保つよう書いていますが、商品フィードのキャンペーンに適用されるかは書いていません（クリエイティブ強化の記事）。

この記事で分からないこと

  • 日本のアカウント・日本円のカタログで、商品フィードを作って配信できるか（冒頭の節を参照）
  • 日本語の商品名・説明の扱い。 文字コードはUTF-8と書かれていますが、言語の記載はありません
  • 広告の見え方の細部。 1つの広告に商品がいくつ、どの順で並ぶかは書かれていません
  • 星の表示に使われる項目と、Not approved の商品ごとの理由
  • 管理画面のホストURLの自動の取り込みの頻度
  • クリエイティブ強化が商品フィードの広告に適用されるか

  • [ ] 色・サイズ違いを別の行にし、group_id でまとめた
  • [ ] 商品ページと画像のURLが外部から開け、OAI-AdsBot・OAI-SearchBotを止めていない
  • [ ] 100件ほどの見本で取り込みを試し、Upload History のエラーを直した
  • [ ] 4つの件数を差し引きで読まず、広告グループの商品数で対象を確かめた
  • [ ] 全件を1日1回以上送り直す方式・担当・時刻と、セールの開始・終了の送り直しを決めた
  • [ ] 販売を止める商品は行を消さず out_of_stock で送る手順にした
  • [ ] 商品URLのトラッキングが旧方式なら、2026年11月5日までの切り替えを管理者に依頼した

よくある質問

Q. Google向けの商品フィードを、そのまま使えますか。 原典はGoogleのフィードとの互換を説明していません。仕様には、item_id の別名として id や sku、group_id の別名として item_group_id を受け付けるという記載があります。ただし seller_name のような必須の項目の抜けや値の形式の違いは取り込みの失敗の原因になるため、項目名と値を仕様と照らしてから使います（当社の見解）。

Q. 商品ごとに入札額を変えられますか。 開発者向けドキュメントの表では、入札は広告グループで設定する項目で、商品ごとの入札の項目は書かれていません。ヘルプは、独自の値（例：bidding_tier）を ads_metadata に入れて広告グループを組み分ける例を示しています。入札を変えたい商品群にラベルを付け、広告グループを分けます（当社の提案）。

Q. 楽天市場やAmazonの店舗の商品ページを、リンク先にできますか。 原典はこの点に直接答えていません。商品ファイルの仕様では、モールの商品は seller_name に販売者、marketplace_seller に購入するモールを書きますが、後者は設定が要るとされています。広告ポリシーは、リンク先が広告主と広告の商品に明確に関係することを求め、ヘルプには、別のドメインのリンク先を使うと事業者の確認の承認が先に要る場合があるとあります。当社は、自社サイトの商品ページで始めることを勧めます。

Q. 商品が数千点あります。広告グループはいくつに分ければよいですか。 原典に数の目安はありません。当社は、入札や訴求を変えたい単位（例：主力の商品群とそれ以外）で2〜3の広告グループから始め、商品ごとの実績を見てから分けることを勧めます。分けすぎると、それぞれの実績が少なく判断しにくくなります（アカウント構成の記事）。

Q. Shopifyアプリと、Ads Managerへの直接の取り込みのどちらを使えばよいですか。 2026年10月29日時点のヘルプでは、Shopifyアプリは現在、米国のすべてのShopify事業者が使え、ChatGPT広告の提供地域へは「近く」広げるとされています（時期の記載なし）。10月8日時点のShopifyの記事で紹介した「9月23日から国際展開」の一文は、9月16日の発表のページから10月29日までに削除されました。日本のストアでアプリを使えない場合は、Shopifyから書き出した商品データを仕様に合わせてAds Managerに取り込みます（当社の見解）。

まとめ

  • 必須は9項目。is_ads_eligible で広告の対象を決め、独自のラベルで商品を選ぶ（配信地域は国単位から絞れない）
  • 取り込んだ商品は2週間で失効する。ホストURLかSFTPで、全件を1日1回以上送り直す
  • 4つの件数は差し引きで読まない。Productsタブは配信の実績がある商品だけ
  • セールの日付では価格は切り替わらない。販売を止める商品は out_of_stock で送る
  • 日本のアカウント・日本円のカタログで使えるかは、原典に明記がない
