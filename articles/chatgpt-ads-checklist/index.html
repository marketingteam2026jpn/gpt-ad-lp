この記事の要点

  1. 確かめる頻度は、数字が反映される速さに合わせます。 表示・クリックは約15分ごとに更新され、消化額は約7〜8時間遅れ、成果は24〜48時間かかることがあります。日次は「配信が止まっていないか」を見て、成果の判断は週次に回すことを勧めます（当社の提案）。
  2. 日次は、配信の数字より先に状態と通知を見ます。 審査・事業者の確認・予算・終了日・請求のどれかで、配信は止まり得ます。日予算は日曜〜土曜の週の上限があり、早く使い切ると「有効」のまま止まることがあります。
  3. 変更の前に、作成後に戻せない設定かを確かめます。 目的・課金方式・成果イベントはその場で変えられず、総額予算から日予算への変更は戻せません。名前の変更で審査が始まることもあります。変更後は、保存した値が残っているかを開き直して確かめます。

読んでほしい人：ChatGPT広告の配信を始めた、または始める予定の運用担当者と、その確認の分担を決める責任者。代理店に運用を任せていて、自社で確かめる項目を決めたい広告主。
この記事で扱わないこと：画面の見方はAds Managerの使い方の記事、週次の数字の読み方はレポートの見方の記事、続ける・止めるの判断の基準はテスト運用の記事で扱います。本稿は確認の手順の一覧です。

このチェックリストの使い方

各項目は「何を確かめるか」「なぜか」「詳しい記事」の順に書いています。社内の手順書やスプレッドシートに、そのままコピーして使えます。用語の意味は用語集で確かめられます。

日次のチェックリスト

日次は「止まっていないか」と「使いすぎていないか」を見ます。成果の増減で設定を変える判断は、ここではしません。

  • [ ] キャンペーン・広告グループ・広告の状態が Serving か。 Not serving のときは、状態にカーソルを合わせて理由を読みます。審査・アカウントの確認・予算・終了日・請求のどれかで止まり得るためです（配信されないときの記事）
  • [ ] Ads Managerのバナーと、請求・確認の通知メールを見た。 支払いが失敗すると配信が止まり得ます。事業者の確認が必要なときはバナーが出ます。一定の消化の後に、追加の確認を求められることもあります（開設・アカウント審査の記事）
  • [ ] 表示回数とクリックが続いているか。 約15分ごとに更新されるため、配信の確認に使えます。公開したばかりのキャンペーンで原因が見当たらない場合、ヘルプは「配信が0」とサポートに伝える前に少なくとも24時間待つよう書いています。明らかなエラーや請求・審査の問題は待たずに連絡します（Ads Managerの使い方の記事）
  • [ ] 広告グループの入札の警告（Low bid など）を見た。 警告は実際のオークションの結果に基づき、推奨の入札額とは違うことがあります。入札を上げても配信は保証されません（入札戦略の記事）
  • [ ] 日予算のキャンペーンで、今日と今週（日曜〜土曜）の消化を見た。 1日の消化は日予算の2倍まで、週は7倍までです。週の上限を早く使い切ると、有効のままでも次の週まで止まることがあります（予算の消化の記事）
  • [ ] 消化額の反映の範囲を、Spend の見出しで確かめてから読んだ。 消化額は約7〜8時間遅れるため、0と表示されていても課金がないとは限りません（レポートの見方の記事）
  • [ ] 前日まで届いていた成果のイベントが、急に止まっていないか。 成果の列は24〜48時間かかりますが、送信のエラーや、動いていた連携が急に止まった場合は、待たずに調べるようヘルプは書いています（計測のトラブル対応の記事）

週次のチェックリスト

週次で、成果と計測の質を読みます。期間は日曜〜土曜の完了した週にそろえると、予算週と合わせて読めます（当社の提案）。

  • [ ] 成果は、直近2日を除き、帰属期間をそろえて比べた。 成果は24〜48時間かかり、直近の合計は処理の途中で変わります。帰属期間を変えるとレポートの数が変わります（レポートの見方の記事）
  • [ ] イベント品質の警告を、データソースごとに見た。 警告は設定を見直す箇所を示すもので、配信の成果の予測ではありません。点数を上げるために余分なイベントを送ったり、時刻を変えたりしてはいけません（計測のトラブル対応の記事）
  • [ ] Ads Manager・GA4・CRMの件数を、同じ期間・タイムゾーン・成果の範囲で比べた。 帰属の方法や期間が違うため、数が違うこと自体はエラーとは限りません（GA4連携の記事）
  • [ ] 国とプラットフォームの内訳で、意図しない配信がないか見た。 すべての国を選んで一部を除外しても、除外していない国には配信され得ます。米国だけにするには米国を明示的に選びます（ターゲティングの記事）
  • [ ] 新しく入稿した広告の審査の結果を見た。 否認の理由が当てはまらないと考えるときは、異議申し立て（appeal）か Request Review を使います（審査の記事）
  • [ ] サイトを変えた週は、LPが表示でき、OAI-AdsBot が止められていないか確かめた。 OAI-AdsBot の許可は必須です。robots.txt だけでなく、WAF・CDN・ボット対策でも止まることがあります（クローラー許可の記事）
  • [ ] 商品フィードを使う場合、フィードの更新が続いているか。 アップロードした商品は2週間で失効するため、ヘルプはホストしたURLかSFTPでの自動のアップロードを勧めています（商品フィードの記事）
  • [ ] 日別の値をCSV（Export daily values）で書き出し、設定と一緒に保存した。 後から取り直すと、処理の途中だった数字が変わっていることがあります（レポートの見方の記事）
  • [ ] その週の変更の記録を、週のレビューに付けた。 同じ週に複数を変えると、どれが効いたか分からなくなります（テスト運用の記事）

月次のチェックリスト

月次は、請求・権限・方針のように、配信の数字には出にくいものを確かめます。

  • [ ] 請求書・領収のメールと、レポートの消化額を同じ期間・タイムゾーンで照らし合わせた。 カード払いでは支払いしきい値に達したときと月末に請求され、同じ額の請求書が続いても重複とは限りません。請求とレポートは更新の時期が違います（支払い・請求の記事）
  • [ ] カードの請求が失敗していないか、支払いしきい値が変わっていないかを見た。 しきい値は支払いの実績などで自動で上がることがあり、自分では変えられません（支払い・請求の記事）
  • [ ] 請求プロファイルの事業者名・住所・請求書の送付先メールが最新か。 請求に関わる連絡は、このメールに届きます（支払い・請求の記事）
  • [ ] ユーザーと役割を棚卸しした。 退職・異動・代理店の契約終了でアクセスを外します。直接の役割を外しても、グループから高い役割が付いていればアクセスは残ります（権限・ユーザー管理の記事）
  • [ ] APIキーと外部の連携（計測パートナー・HubSpot・Shopify・プラグイン）を、誰が何に使っているか記録した。 APIキーは広告アカウントごとで、使っていない連携が残ると管理の抜けになります（当社の提案。一括入稿とAPIの記事）
  • [ ] コンテキストヒント・広告文・LPの価格・キャンペーンの情報が最新か。 ヘルプは、機能・価格・キャンペーン・在庫・対応地域が変わったらヒントを更新するよう書いています（コンテキストヒントの記事）
  • [ ] クリエイティブ強化の設定を、アカウントの既定とキャンペーンごとに確かめた。 2026年10月30日から、新規・既存のセルフサーブとBPOのキャンペーンで既定で有効です（営業担当が管理するアカウントには影響しない）。キャンペーンの設定がアカウントの既定より優先されます（クリエイティブ強化の記事）
  • [ ] カスタムオーディエンスのリストを更新した（使う場合）。 作り直さずに、メンバーを追加・削除・置き換えできます。使ってよいデータかの確認も合わせて行います（カスタムオーディエンスの記事）
  • [ ] 広告ポリシーの版の履歴と、ヘルプの主な変更を確かめた。 ポリシーは末尾に改訂の内容があります。機能の提供段階や仕様は、ベータの間に変わり得ます（最新アップデートの記事）

変更する前のチェックリスト

ChatGPT広告には、作成後にその場で変えられない設定があります。変更の前に、次を確かめます。

  • [ ] 変えたいのは、作成後に変えられない設定ではないか。 目的・課金方式・成果イベント（成果最適化）は変えられず、新しいキャンペーンか複製で対応します。国・通貨・タイムゾーンはアカウントの作成後に変えられません（成果最適化の記事）
  • [ ] 予算の種類を変える場合、戻せないことを承知している。 総額予算から日予算には変えられますが、日予算から総額予算には戻せません（予算の消化の記事）
  • [ ] 日予算を日中に上げると、その日の上限は、その日の最も高い日予算の2倍になると理解している。 週の途中の変更は、週の上限が按分されます。固定の入札では、日予算を広告グループの実効の入札額より下げられません（予算の消化の記事）
  • [ ] 総額予算を減らす場合、消化済みの額を下回っていない。 消化済みと同じ額にすると配信が止まります。予算や終了日を変えると、ペーシングが計算し直されます（予算の消化の記事）
  • [ ] Brand Name・Legal Name を変える影響を確かめた。 Brand Name の変更は審査が始まり、承認まで配信が止まります。Legal Name の変更は事業者の審査がやり直しになり、配信が止まることがあります。Account Name の変更は審査に影響しません（開設・アカウント審査の記事）
  • [ ] リンク先のドメインを変える場合、事業者の確認が先に要らないか確かめた。 確認が必要なセルフサーブのアカウントでは、別のドメインのリンク先を使うと、確認の承認が先に求められることがあります（開設・アカウント審査の記事）
  • [ ] 一括編集は、最新の Export for edit のファイルから始めた。 コンテキストヒントは追記ではなく置き換えになるため、残したいヒントもすべて書きます（一括入稿とAPIの記事）
  • [ ] 最初のキャンペーンで開始日を決めたい場合、日付を設定する前に公開していない。 最初のキャンペーンは公開前に日付を選べないことがあり、ヘルプは日付の設定のためだけに公開しないよう書いています（Ads Managerの使い方の記事）
  • [ ] 変更前の値と、変える理由を記録した。 後から効果を読むときと、元に戻すときに使います（テスト運用の記事）

変更した後のチェックリスト

  • [ ] 保存した後にページを開き直し、値が残っているか確かめた。 当社の画面では2026年10月5日、広告の自動カスタマイズの設定をOffにしても、Onに戻ることがありました（当社の観察。仕様として確かめたものではありません）
  • [ ] 下書きから公開する前に、キャンペーンの予算を入れ直した。 当社の画面では2026年10月5日、広告の下書きにキャンペーンの予算が保存されませんでした（当社の観察）
  • [ ] 変更した広告・キャンペーンの状態が Serving か確かめた。 管理画面のその場の編集で審査がやり直しになるかは、ヘルプに書かれていません。Brand Name の変更のように審査が始まる変更もあるため、変更後の状態を見ます（Ads Managerの使い方の記事）
  • [ ] 成果の設定を直した場合、新しい実際の行動で受信と帰属を確かめた。 設定の食い違いを直しても、過去の分は埋まりません（計測のトラブル対応の記事）
  • [ ] 1回に1つの変更にした。 同時に複数を変えると、どの変更が効いたか判断できません（当社の提案。テスト運用の記事）

止めるとき・担当が替わるときのチェックリスト

  • [ ] 止めたい時刻より前に、一時停止するか終了日を設定した。 停止の後も、最大24時間ほど広告が表示されることがあり、その間の費用も請求されます（Ads Managerの使い方の記事）
  • [ ] 事業者の確認が終わっていないことを、配信を止める手段にしていない。 確認の前に配信と課金が始まるアカウントもあるため、ヘルプは、準備ができていなければキャンペーンを一時停止して状態を確かめるよう書いています（開設・アカウント審査の記事）
  • [ ] アクセスできなくなっても、配信が止まったと考えない。 ほかの権限のある管理者に停止を頼みます。誰もアクセスできない場合は、配信が続いている可能性があることと、止めたいキャンペーンをサポートに伝えます（権限・ユーザー管理の記事）
  • [ ] 担当を外す前に、別の管理者を付けた。 広告アカウントには、少なくとも1人の管理者が必要です。直接の役割とグループの両方を確かめます（権限・ユーザー管理の記事）
  • [ ] 代理店との契約を終えるとき、代理店のユーザー・APIキー・外部の連携を外し、以後の確認の担当を決めた。 当社の提案です（自社運用と代理店支援の記事）
  • [ ] アカウントを使わなくなる場合、残高を精算し、続けたくないキャンペーンを停止・終了した。 自分で削除できない場合は、ヘルプの案内に沿ってサポートに相談します（支払い・請求の記事）

この記事で分からないこと

  • 消化や成果の異常を知らせる通知の機能。 確認した公式資料に、Ads Managerで消化額や成果のしきい値を決めて通知を受け取る機能は書かれていません
  • 画面の日本語表記。 本記事はヘルプの英語の名前で書いています
  • 反映の時間の保証。 15分・7〜8時間・24〜48時間はいずれも目安で、ヘルプも変わり得るとしています
  • 当社の観察（2026年10月5日）の現在の状況。 自動カスタマイズの設定が戻る、下書きに予算が保存されない、という挙動が今も起きるかは確かめていません
  • 確認にかかる時間。 アカウントの規模や構成で変わるため、目安を示していません

よくある質問

Q. 週末や連休の前に、確かめておくことはありますか。 日予算のキャンペーンは、1日に日予算の2倍まで使われることがあり、週（日曜〜土曜）の上限は7倍です。連休中に確認できない場合は、休みに入る前に予算の週の消化と状態を見て、止めたい時刻があるなら、停止が最大24時間遅れることを見込んで終了日を設定しておくことを勧めます（当社の提案）。連休の明けには、成果は24〜48時間の遅れを除いて読みます。

Q. 担当者が1人しかいない場合、最低限どれを見ればよいですか。 当社は、日次は「状態」「通知メール」「予算の週の消化」の3つ、週次は「成果」「イベント品質」の2つを最低限として勧めます。あわせて、広告アカウントの管理者を2人以上にしておくと、担当者が不在のときも停止や変更ができます（管理者が少なくとも1人必要なのはヘルプの要件で、2人以上は当社の提案です）。

Q. 代理店に運用を任せている場合、広告主の側では何を確かめればよいですか。 当社は、月次の請求とレポートの照合、ユーザーと役割の棚卸し、管理者の役割を自社の担当者にも残すこと、週次の成果を自社のCRMの数と比べることを勧めます。設定の変更は代理店が行っても、請求とアクセスの管理は広告主の責任で確かめる、という分け方です（自社運用と代理店支援の記事）。

Q. Ads Managerプラグインで、日々の確認を任せられますか。 ヘルプによると、プラグインは成果の分析、配信の問題の切り分け、優先順位をつけた推奨ができ、変更は確認したうえで行います。期間を指定しない場合は、直近の完了した7日間を見ます。当社は、確認の要約や設定の点検に使い、公開・予算・入札の変更は人が確かめることを勧めます（Ads Managerプラグインの記事）。

Q. このチェックリストと、よくある失敗の記事はどう使い分けますか。 本稿は、決まった頻度で確かめる項目の一覧です。よくある失敗と対策の記事は、計測・審査・予算・広告文で起きやすい失敗を、起きることと原因から引けるようにまとめています。チェックリストの項目で引っかかったときに、原因を探すのに使えます。

まとめ

  • 頻度は反映の速さに合わせる。日次は表示・クリックと状態で「止まっていないか」、成果は週次で直近2日を除いて読む（当社の提案）
  • 日次は状態・通知メール・入札の警告・予算週の消化を見る。消化額は約7〜8時間遅れる
