この記事の要点

  1. llms.txt は、AIのエージェントにサイトの概要と主要なページの場所を伝えるための、Markdown のファイルの提案です。 2024年9月3日に公開され、2026年8月に第2版になりました。標準化団体の規格ではなく、提案の文書が仕様の説明を兼ねています。
  2. Google 検索は llms.txt を使わないと明記しています。 置いても Google 検索での表示や順位には良くも悪くも影響しない、ただし他のサービスのために置くのは問題ない、という立場です。OpenAI・Anthropic・Perplexity・Apple・Microsoft の公式資料にも、自社のクローラーや回答で llms.txt を読むという記載は、本記事で確認した範囲ではありませんでした。
  3. 置くなら、手間を小さく保ち、効果を前提にしないことを勧めます（当社の見解）。 先にやるのは、検索・回答用のクローラーを止めていないかの確認と、元のページの情報を正確にすることです。

読んでほしい人：外注先や社内から「LLMO対策として llms.txt を置くべきか」と聞かれている、または提案を受けているWeb担当・マーケティング責任者。
この記事で扱わないこと：robots.txt での AI のクローラーの許可・拒否はAIクローラーの許可設定の記事、構造化データは構造化データとLLMOの記事で扱います。

llms.txtとは：提案の目的

llms.txt は、llmstxt.org で公開されている提案です。提案の文書には、作者（Jeremy Howard 氏）、公開日（2024年9月3日）、最終更新日（2026年8月10日）が書かれています。副題は「エージェントがWebサイトを使うのを助ける情報を、/llms.txt というファイルで提供することを標準化する提案」です。

提案の背景は次のように説明されています。

  • AIのエージェント（利用者の代わりに調べものや作業をするAI）は、ドキュメントや製品のページを日常的に読んでいる
  • しかし Web のページは人向けに作られており、ナビゲーション・広告・JavaScript を取り除いて内容だけを取り出すのは難しい
  • AIが一度に読める量（コンテキスト）は以前より増えたが、多くのサイトは全体が入りきらない

そこで、サイトの概要と、詳しい情報がどこにあるかを、短い Markdown のファイルにまとめておく、というのが提案の中身です。提案の文書は、エージェントは llms.txt を見て必要な情報を探し、関連するリンクをたどることを想定している、と書いています。

提案の文書は、利用が最も多いのはソフトウェアのドキュメントで、コーディングを手伝うAIが API の説明やチュートリアルを探すのに使っていると書いています。企業が事業の構成や方針を示す使い方も挙げています。

「標準」と呼ばれることがありますが、提案の文書自身は、仕様はコミュニティの意見を受け付けており、GitHub のリポジトリでこの「非公式の概要」を管理していると書いています。IETF などの標準化団体が定めた規格ではありません。

置き場所と書式

提案の第2版の内容を、置き場所と書式に分けて整理しました。

項目

提案の内容

ファイル名と場所

llms.txt。サイトのルート（/llms.txt）か、任意のパス（例：/docs/llms.txt）。そのパスの下のページが対象。複数当てはまるときは最も具体的なものを使う

1行目

H1（# で始まる見出し）でサイトやプロジェクトの名前。これだけが必須

要約

引用（> で始まる行）で、ファイルを理解するのに必要な短い要約

詳細

見出し以外の Markdown（段落・箇条書きなど）で、補足の説明

ファイルの一覧

H2（## で始まる見出し）で区切り、[名前](URL) のリンクを箇条書きで並べる。リンクの後に「:」と短い説明を付けられる

Optional の節

慣例として、短く済ませたいときに飛ばしてよい二次的なリンクを置く

ページの Markdown 版

元のページと同じ URL に .md を付けたもの（page.html.md）か、拡張子を .md に置き換えたもの（page.md）を用意することも提案している

見つけてもらう方法

ページの Markdown 版は rel="alternate" type="text/markdown"、llms.txt は rel="describedby" のリンク関係で示す。HTML の link 要素か、HTTP の Link ヘッダーで

作り方の指針として、提案の文書は、簡潔で明確な言葉を使う、リンクに短い説明を付ける、曖昧な言葉や説明のない専門用語を避ける、llms.txt だけを渡したAIに自社のことを質問して確かめる、の4つを挙げています。

robots.txt・sitemap.xml との違い

似た名前のファイルと、目的が違います。

ファイル

目的

誰が読むか

自動のツールに、どのアクセスが許容されるかを示す

sitemap.xml

AIのエージェント向けに選んだ、サイトの概要と主要なページへの案内

提案では、利用者を手伝うエージェントが必要なときに読む想定。主要な事業者が読むという公式の記載は確認できない（次の節）

大事なのは、llms.txt はアクセスの許可・拒否の仕組みではないことです。llms.txt にページを載せても、robots.txt でクローラーを止めていれば、そのクローラーは取りに来ません。逆に、llms.txt に載せなくても、robots.txt で許可していればクローラーは取りに来られます。

提案の文書は、llms.txt は主に学習ではなく、回答を作るとき（推論）に役立つと期待しており、実際そのように使われてきた、と書いています。これは提案者の見方で、どの事業者がどう使っているかの公式の資料ではありません。

主要な事業者は使うと言っているか

本記事で確認した公式の資料の範囲で、各社の立場をまとめました。

事業者・製品

公式の資料の記載

Google 検索（AIによる概要・AIモードを含む）

使わない。 置いても表示や順位に良くも悪くも影響しない。他のサービスのために置くのは問題ない（生成AI検索の最適化のガイド。2026年6月15日の変更履歴でこの注記を追加）

Google Chrome の Lighthouse

実験的な「Agentic Browsing（エージェントによる閲覧）」の点検の1つとして、ルートに llms.txt があるかを確かめる。無い（404）場合は「対象外」で、置くのは今のところ任意。取得時にサーバーのエラーが出ると指摘する

OpenAI・Anthropic・Perplexity・Apple・Microsoft・Common Crawl

クローラー・検索の公式資料に、llms.txt を読む・使うという記載はない

Google の中でも、検索と Chrome の開発者向けツールで扱いが違います。Lighthouse の説明は、llms.txt が無いと、エージェントがサイトの全体の構成と主な内容をつかむための巡回に、より時間がかかることがある、と書いています。ただし Lighthouse の Agentic Browsing の分類は、提案中の標準に基づく実験的なもので、0〜100の点数も付けないとされています。どちらの資料も、llms.txt を置くと AI の回答や検索で表示されやすくなるとは書いていません。

もう1つ混同されやすいのが、AIの事業者が自社のドキュメントに llms.txt を置いていることです。提案の文書は、OpenAI・Anthropic・Gemini が自社の開発者向けドキュメントに llms.txt を置いていると紹介しています。実際、OpenAI のクローラーの資料の冒頭にも、ドキュメントの一覧として llms.txt への案内があります。ただし、これは自社の情報を置く側としての使い方で、他社のサイトの llms.txt を自社の AI の回答に使うという説明ではありません。

書き方の例（企業サイト）

架空の会社のサイトに置く場合の例です。提案の書式に沿って当社が作りました。

# 株式会社サンプル

> 中小企業向けに、勤怠管理のクラウドサービスを提供しています。料金・導入の流れ・よくある質問・問い合わせの窓口を、下のページにまとめています。

- 料金と契約の条件は、料金のページの記載が最新です
- 給与計算の機能はありません（連携しているサービスで対応します）

## サービス

- [サービスの概要](https://example.com/service/): 主な機能と、対象の企業の規模
- [料金](https://example.com/pricing/): プラン別の月額、最低契約期間、解約の条件

## 導入とサポート

- [導入の流れ](https://example.com/onboarding/): 申し込みから利用開始までの手順と期間
- [よくある質問](https://example.com/faq/): 導入・契約・解約についての質問
- [お問い合わせ](https://example.com/contact/): 窓口と受付時間

## Optional

- [導入事例](https://example.com/cases/): 業種別の事例

書くときの考え方です（当社の見解）。

  • 要約の引用には、何の会社で、このファイルに何が載っているかだけを書きます。 宣伝の言葉は入れません
  • 「できないこと」「最新の情報がどこにあるか」を書いておくと、誤った説明を避ける助けになり得ます。効果は確かめられていません
  • リンク先は、公開しているページだけにします。 llms.txt は誰でも読めるファイルです。社外秘の資料や会員限定のページは載せません
  • 料金などの数字は、llms.txt に直接書かず、元のページへのリンクにします。 2か所に書くと、片方だけ古くなるおそれがあります

置くときの手間と注意

置くこと自体は、テキストのファイルを1つ作るだけです。提案の文書は、Yoast SEO や AIOSEO（WordPress のプラグイン）、Wix など、llms.txt を自動で作れる製品も紹介しています（各製品の現在の機能は、それぞれの公式の説明で確かめてください）。

外注先に llms.txt を提案されたら

外注先が LLMO 対策として llms.txt の作成を提案してきたら、次の点を確かめることを勧めます。

  • どのAIのサービスが llms.txt を読むと、どの公式の資料に書かれていますか
  • 作成と更新の費用は、どの作業に対するものですか（自動で作れる CMS もあります）
  • 置いた後、何を測って効果を判断しますか
  • llms.txt より先にやるべきこと（クローラーの許可、元のページの正確さ）は済んでいますか

費用の考え方はSEO・LLMO外注の費用相場の記事で扱います。

期待しすぎないために（当社の見解）

当社は、llms.txt を「置いてもよいが、効果を当てにしない」ものと考えています。理由は3つです。

  1. Google 検索は使わないと明記しており、AIによる概要・AIモードへの効果はない
  2. ほかの主要な事業者も、自社のクローラーや回答で読むと公式に書いていない
  3. AIの回答で自社がどう扱われるかは、元のページの内容と、クローラーが読めるかで決まる部分が大きい（各社の資料が条件として挙げているのは、クローラーの許可と索引）

置く価値が比較的あると当社が考えるのは、API や開発者向けのドキュメントを公開している企業です。提案の文書が最も多い使い方として挙げるのがソフトウェアのドキュメントで、コーディングを手伝うAIが読む場面だからです。一般の企業サイトでは、llms.txt の作成を優先順位の上に置く理由は、本記事で確認した資料からは見つかりませんでした。

この記事で分からないこと

  • llms.txt を置くと、AIの回答で引用されやすくなるか。 どの事業者の公式資料にも、そうした効果の記載はありません。
  • 公式に書いていない事業者が、実際には llms.txt を読んでいるか。 サーバーのアクセスの記録で、llms.txt への要求があるかを自社で確かめることはできますが、回答に使われたかまでは分かりません。
  • llms.txt を自動で作る各製品の、現在の機能。 提案の文書の紹介に基づいており、各製品の公式の説明は確かめていません。
  • 提案が標準化団体の規格になるか。 提案の文書に、その予定は書かれていません。

llms.txt を置く前のチェックリスト

  • [ ] 検索・回答用のクローラー（OAI-SearchBot・Claude-SearchBot・PerplexityBot・Googlebot など）を robots.txt・WAF で止めていない
  • [ ] 主要なページ（サービス・料金・よくある質問・問い合わせ）の情報が正確で、最新の情報がどこにあるかが分かる
  • [ ] llms.txt を置く目的（どのサービス・どの使われ方を想定するか）を決めた
  • [ ] 1行目に H1 でサイト名、次に引用で短い要約を書いた
  • [ ] 載せるのは公開しているページだけで、料金などの数字は元のページへのリンクにした
  • [ ] /llms.txt にアクセスして、正しく返る（サーバーのエラーにならない）
  • [ ] ページの追加・削除・URLの変更のときに、llms.txt も直す担当を決めた

よくある質問

Q. llms.txt を置くと、Google の検索順位に悪い影響はありますか。 Google は、llms.txt を置いても Google 検索での表示や順位には良くも悪くも影響しないと書いています。Google はさまざまな種類のファイルを見つけて索引に登録することがありますが、それはファイルが特別に扱われるという意味ではない、とも説明しています。

Q. llms.txt と llms-full.txt は何が違いますか。 llms-full.txt という呼び方も見られますが、2026年8月の第2版の提案の文書には、この名前は出てきません。第2版は、llms.txt に概要とリンクを置き、詳しい内容はページごとの Markdown 版に置く形を提案しています。

Q. robots.txt で AI のクローラーを止めていますが、llms.txt を置けば読んでもらえますか。 llms.txt はアクセスの許可・拒否の仕組みではありません。robots.txt で止めているクローラーは、llms.txt があっても取りに来ないと考えるのが自然です（当社の見解）。AIの検索・回答に出たい場合は、まず robots.txt で検索・回答用のクローラーを許可します。

Q. 日本語で書いてもよいですか。 提案の文書に、言語の決まりはありません。書式として決められているのは、H1・引用・H2 で区切ったリンクの一覧などの構造です。サイトの主な読み手の言語で書き、URL とページの名前が正確であることを優先します（当社の見解）。

Q. 置いた効果は、どう確かめればよいですか。 本記事で確認した範囲では、llms.txt の効果を測る公式の方法はありません。サーバーのアクセスの記録で /llms.txt への要求があるかは確かめられますが、回答に使われたかは分かりません。AIの回答での自社の表示の確かめ方はAI回答での自社表示の測り方の記事で扱います。

  • 書式は、H1（必須）・引用の要約・補足・H2 で区切ったリンクの一覧。ページごとの Markdown 版とリンク関係も提案している
  • Google 検索は使わないと明記（表示・順位に良くも悪くも影響しない）。Chrome の Lighthouse は実験的な点検で存在を確かめる。ほかの主要な事業者に、読むという公式の記載は確認できなかった
  • AIの事業者が自社のドキュメントに置いていることと、他社のサイトの llms.txt を読むことは別
  • 置くなら手間を小さく、公開ページだけ、数字は元のページへ。先にクローラーの許可と元のページの正確さを
