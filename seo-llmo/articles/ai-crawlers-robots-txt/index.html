AIクローラーの許可設定｜GPTBot・OAI-SearchBot・Google-Extended・PerplexityBot

企画・編集：GPT広告専門店（株式会社Ikigai）公開：2026年11月4日／情報確認：2026年11月4日

AIのクローラーは、学習用・検索や回答用・利用者の操作による取得の3種類に分かれます。OpenAI・Google・Anthropic・Perplexity・Apple・Microsoftの公式資料から、名前ごとの用途、学習は止めて回答には出る設定、robots.txtの例、WAF・CDNで止める問題を整理します。

本記事は、OpenAI・Google・Anthropic・Perplexity・Apple・Common Crawl のクローラーの公式資料、Microsoft（Bing）の公式ブログ、robots.txt の標準（RFC 9309）に基づいています（いずれも2026年11月4日に本文を確認）。robots.txt の例と設定の考え方は株式会社Ikigaiの見解で、各社の資料の範囲で作っています。

この記事の要点

  1. AIのクローラーは、目的で3種類に分かれます。 AIの学習用（GPTBot・ClaudeBot など）、検索や回答のための巡回用（OAI-SearchBot・Claude-SearchBot・PerplexityBot など）、利用者の操作に応じた取得（ChatGPT-User・Perplexity-User など）です。多くの事業者が、これらを別々の名前で管理できるようにしています。
  2. 「学習には使われたくないが、回答には出たい」は、多くの事業者で設定を分けられます。 ただし、名前の使い方は事業者ごとに違います。Googleの Google-Extended は Google 検索の掲載や順位に影響しないと明記されており、止めても AI による概要からは外れません。
  3. robots.txt だけでは足りません。 WAF・CDN・ボット対策が検索用のクローラーを止めていることがあり、利用者の操作による取得には robots.txt が当てはまらないこともあります。設定は、各社の公開するIPアドレスの一覧と組み合わせて確かめます。

読んでほしい人：AIの学習への利用を止めるべきか、AIの検索・回答には出したいかを、社内で決める必要があるWeb担当・情報システム担当・マーケティング責任者。
この記事で扱わないこと：ChatGPT広告の審査に必要な OAI-AdsBot の設定は、目的が違うためChatGPT広告のクローラー許可の記事で扱います。

クローラーは、Webのページを自動で取りに来るプログラムです。AIの事業者は、目的ごとに名前（ユーザーエージェント）を分けています。

Common Crawl に集められない

Microsoft は、クローラーで集めたWebの内容を、学習や、Bing・Copilot・Microsoft 365 の回答の根拠に使うと説明しています。2026年10月30日の Bing の公式ブログによると、学習（AI Training）と回答の根拠（AI Grounding）を別々に指定する新しい方法を、2027年2月1日からクロールの際に尊重します。学習はサイト・パス単位なら robots.txt の共通の名前（__usage_ai-training）、ページ単位なら Bingbot 向けの meta タグか X-Robots-Tag で、回答の根拠はページ単位だけで指定します。これまでの NoArchive・NoCache の指定は置き換えられ、2027年3月1日以降は学習・回答の根拠の指定として読まれなくなります。

なお、OpenAI には広告の審査のための OAI-AdsBot もあります。これは ChatGPT 広告として提出されたページだけを訪れ、集めたデータは学習に使わないと説明されているクローラーで、AIの検索や学習の方針とは別に決めます（ChatGPT広告のクローラー許可の記事）。

Google-Extended と Googlebot の関係

名前から AI による概要の設定と取り違えやすいのが、Google-Extended です。Googleのクローラーの資料は、次のように書いています。

  • Google-Extended には、独自のユーザーエージェントの文字列がない。クロールは既存の Google のクローラーで行い、robots.txt の名前は「指定のため」に使う
  • 対象は、Gemini アプリと Vertex AI の Gemini API を支える将来の Gemini モデルの学習と、Gemini アプリ・Vertex AI の「Grounding with Google Search」でのグラウンディング
  • Google-Extended は、Google 検索でのサイトの掲載に影響せず、Google 検索の順位の要因としても使われない

つまり、Google-Extended を止めても、Google 検索の AI による概要・AI モードからは外れません。Google の「AI 機能とウェブサイト」のページも、AI は検索に組み込まれているため、検索のクロールの管理は Googlebot 向けの robots.txt で行うと書いています。AI による概要などに出したくない場合は、Search Console の「検索の生成 AI 設定」や nosnippet を使います（AIO対策の記事）。逆に、Search Console の生成AIの設定で除外しても、AIの学習には影響しないとヘルプは書いています。学習を止めたいなら Google-Extended、AI による概要に出したくないなら生成AIの設定、と分けて考えます。

Googleは、2027年初頭に、業界で共通の学習の指定（AIPREF。robots.txt に「user-agent: __usage_ai-training」と書く形）に対応する予定だとも書いています。Microsoft も、同じ __usage_ai-training の指定を2027年2月1日からクロールの際に尊重するとしています。これはインターネットの標準を決める IETF の作業部会の草案（Internet-Draft）に基づくもので、最終的な標準に向けた作業は続いていると Microsoft は書いています。OpenAI も2026年10月30日に、robots.txt で基盤モデルの学習への使用について意向を示す共通の指定に従うと発表しました。実装は「今後数か月のうち」とされ、詳細は実装の際に改めて知らせるとしています。この指定は、GPTBot など既存の robots.txt での設定を置き換えるものではなく、既存の設定も引き続き適用されると書いています。

当社の見解では、企業のサイトで最初に決めたいのは「学習を止めるか」ではなく、「AIの検索・回答に出たいか」です。検索・回答用のクローラーを止めると、OpenAIは検索の回答に出ないと、Anthropic は検索の結果での見え方が下がり得ると書いています。学習を止める方針の会社でも、検索・回答用の名前は分けて許可するのが、各社の資料から素直に読める組み合わせです。

Common Crawl については、ページの説明は「誰でも利用・分析できる公開の保存庫」までで、データを誰が何に使うかは書かれていません。止めるかどうかは、自社の方針で判断します。

robots.txt の書き方の例

学習用は止め、検索・回答用は許可する例です。各社の資料にある書き方をもとに、当社がまとめました。自社のサイトにそのまま使う前に、各社の最新の資料で名前を確かめてください。

# 学習用・学習の指定（止める）
User-agent: GPTBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: Google-Extended
Disallow: /

User-agent: Applebot-Extended
Disallow: /

# Common Crawl（公開の保存庫。止めるかは自社の方針で）
User-agent: CCBot
Disallow: /

# 検索・回答用（許可する）
User-agent: OAI-SearchBot
Allow: /

User-agent: Claude-SearchBot
Allow: /

User-agent: PerplexityBot
Allow: /

# それ以外のクローラー
User-agent: *
Allow: /

書くときに見落としやすい点です（いずれも robots.txt の標準 RFC 9309 と各社の資料による）。

  • 標準では、クローラーは自分の名前に一致するグループだけに従い、一致がないときだけ「User-agent: *」に従います。 「*」で全体を止めているサイトでは、検索用のクローラーの名前で「Allow」のグループを作らない限り、そのクローラーも止まります
  • robots.txt はホスト（サブドメイン）ごとに置きます。 Anthropic も、止めたいサブドメインごとに書くよう求めています
  • 一部だけ止めることもできます。 許可と不許可が重なるときは、パスに最も長く一致する規則が使われます。Google-Extended の資料にも、/archive/ を止めつつ一部だけ許可する例があります
  • Apple は、Applebot の名前が無く Googlebot の名前がある場合、Googlebot 向けの規則に従います。 Googlebot だけを止めると、Apple の検索にも影響し得ます
  • Crawl-delay（取りに来る間隔の指定）は、対応が分かれます。 Anthropic は対応、Apple は従わないと書いています

共通の学習の指定（User-agent: __usage_ai-training）は、Microsoft が2027年2月1日からクロールの際に尊重し、Google は2027年初頭に対応する予定です。OpenAI も2026年10月30日に、共通の指定に従うと発表しましたが、実装の時期と方法の詳細はまだ示されていません。本記事で確認したほかの事業者（Anthropic・Perplexity・Apple・Common Crawl）の資料には、この指定への対応の記載はありません。当面は、上の例のように各社の名前ごとの指定が必要です。

robots.txt で止められないもの・効かないもの

robots.txt は、クローラーに「来ないでほしい」と伝える仕組みで、アクセスを防ぐ仕組みではありません。Googleも、robots.txt はクローラーの振る舞いを強制できず、守るかはクローラー次第だと書いています。

WAF・CDNのボット対策で止めてしまう問題

robots.txt で許可していても、WAF（Webアプリケーションのファイアウォール）やCDNのボット対策が、検索用のクローラーを止めていることがあります。Googleは、AI による概要・AI モードに向けたSEOの基本として、robots.txt と、CDN・ホスティングの両方でクロールを許可することを挙げています。OpenAIも、ホストやCDNが OpenAI の公開する IP アドレスからのアクセスを通しているかを確かめるよう書いています。

Perplexity の資料には、具体的な設定の手順があります。Cloudflare では、ユーザーエージェントと各ボットのIP範囲を組み合わせたルールで、ほかの防御のルールをスキップさせ、そのルールをブロックするルールより上に置きます。ただし、Cloudflare の Bot Fight Mode はこのルールではスキップできないとも書いています。AWS WAF では、IP の一覧とユーザーエージェントの一致を組み合わせた許可のルールを、ブロックのルールより先に評価させます。

この記事で分からないこと

  • 学習を止める前に集められた内容の扱い。 各社の資料は、今後のクロールへの指定として説明しています。
  • Common Crawl のデータを、どの事業者が何に使っているか。 Common Crawl のページには書かれていません。
  • Bing のヘルプに書かれた細かい設定。 Bing のヘルプのページは、本記事の取得の方法では本文を確認できなかったため、公式ブログの範囲で書いています。
  • 本記事で扱っていない事業者のクローラー。 本記事は、OpenAI・Google・Anthropic・Perplexity・Apple・Common Crawl・Microsoft の公式資料の範囲です。
  • AIの検索・回答用のクローラーを許可したときに、引用がどれだけ増えるか。 許可は条件であって、表示は各社とも保証していません。

Web担当・セキュリティ担当に渡すチェックリスト

  • [ ] 社内で「AIの検索・回答に出たいか」と「学習への利用を止めたいか」を分けて決めた
  • [ ] robots.txt で、OAI-SearchBot・Claude-SearchBot・PerplexityBot・Googlebot・Applebot を意図せず止めていない（「User-agent: *」の不許可も確認）
  • [ ] 学習を止める場合、GPTBot・ClaudeBot・Google-Extended・Applebot-Extended などを名前で指定した
  • [ ] Google-Extended を止めても AI による概要からは外れないこと、外したいなら Search Console の設定を使うことを共有した
  • [ ] すべてのサブドメインに robots.txt がある（または意図して置いていない）
  • [ ] WAF・CDN・ボット対策で、検索用のクローラーの公開IPを止めていない。許可のルールはIPの一覧と組み合わせている
  • [ ] 会員限定・社外秘の情報は、robots.txt ではなくログインで守っている
  • [ ] NoArchive・NoCache を使っている場合、2027年3月1日までの Microsoft の移行の手順を確認した

よくある質問

Q. robots.txt に何も書いていない場合、AIのクローラーはどう扱われますか。 robots.txt の標準（RFC 9309）では、当てはまるグループも規則もなければ、どの規則も適用されず、アクセスは許可されたものとして扱われます。Microsoft も、学習と回答の根拠の指定はどちらも、指定がなければ「許可」が既定だと書いています。何も書かないことは、学習・検索の両方を許可しているのと同じ状態だと当社は考えます。

Q. GPTBot を止めると、ChatGPT で自社が紹介されなくなりますか。 OpenAI の資料では、ChatGPT の検索の回答に出るかどうかは OAI-SearchBot の設定で管理し、GPTBot の設定とは独立しています。GPTBot だけを止め、OAI-SearchBot を許可していれば、検索の回答の対象からは外れません。ただし、表示は保証されません。

Q. CMS（WordPress や Wix など）で robots.txt を直接編集できません。 Googleの robots.txt の資料も、CMS によっては robots.txt を直接編集できず、検索の設定の画面など別の方法が用意されていることがあると書いています。使っている CMS の説明で、robots.txt の追記の方法を確かめてください。

Q. AIのクローラーのアクセスが多く、サーバーが重くなります。 Anthropic は非標準の Crawl-delay に対応しています。Apple は Crawl-delay に従わない一方、サイトが遅くなったりエラーを返したりすると自動で巡回の速度を落とすと書いています。止める前に、どのクローラーのアクセスが多いかをサーバーのログで確かめ、名前とIPで本物かを見分けます。

Q. 一度止めたクローラーを、あとから許可し直せますか。 robots.txt を書き換えれば許可し直せます。反映には時間がかかり、ChatGPT の検索結果は約24時間、Perplexity は最大24時間が目安とされています。検索の回答に再び出るかどうかは、各社とも保証していません。

まとめ

  • AIのクローラーは、学習用・検索や回答用・利用者の操作による取得の3種類。名前ごとに分けて考える
  • 学習は止めて回答には出す組み合わせは、OpenAI（GPTBot／OAI-SearchBot）、Anthropic（ClaudeBot／Claude-SearchBot）、Apple（Applebot-Extended／Applebot）などで分けられる
  • Google-Extended は Google 検索の掲載・順位に影響しない。AI による概要に出したくないなら Search Console の設定か nosnippet
  • 「User-agent: *」の不許可、サブドメインごとの robots.txt、Apple が Googlebot の規則に従う点に注意する
  • WAF・CDN のボット対策で検索用のクローラーを止めていないかを、IPの一覧と組み合わせて確かめる。Microsoft は2027年2月1日から新しい指定に移る
